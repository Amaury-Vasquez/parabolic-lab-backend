# Parabolic Lab Backend

API backend for a Mexican college educational platform focused on projectile motion (tiro parabolico). Built with FastAPI, SQLAlchemy, and Neon PostgreSQL, using Stack Auth for authentication.

## Tech Stack

- **FastAPI** (async) - Web framework
- **SQLAlchemy 2.0** (async + asyncpg) - ORM
- **Alembic** - Database migrations (async-compatible)
- **Pydantic v2** - Request/response validation
- **Neon PostgreSQL** - Serverless Postgres (project: `autumn-thunder-43526624`)
- **Stack Auth** - Authentication provider (email + password)
- **PyJWT** - JWT verification (ES256 via JWKS)
- **httpx** - Async HTTP client for Stack Auth API
- **uv** - Package manager
- **ruff** - Linter + formatter

## Prerequisites

Before you begin, make sure you have the following installed on your machine:

- **Python 3.11 or higher** - Check with `python3 --version`
- **uv** (Python package manager) - If you don't have it, install it with:

  ```bash
  # macOS / Linux
  curl -LsSf https://astral.sh/uv/install.sh | sh

  # Or with Homebrew
  brew install uv
  ```

You will also need access to:

- A **Neon PostgreSQL** project with a `development` branch
- A **Stack Auth** project with email/password authentication enabled

## Getting Started

Follow these steps after cloning the repository:

### 1. Clone the repository

```bash
git clone <repository-url>
cd parabolic-lab-backend
```

### 2. Install dependencies

`uv` handles virtual environment creation and dependency installation in a single command:

```bash
uv sync
```

This will:
- Create a `.venv/` virtual environment in the project root (if it doesn't exist)
- Install all production and development dependencies from `pyproject.toml`
- Lock exact versions in `uv.lock`

> **Note:** You do **not** need to manually create or activate a virtual environment.
> Use `uv run <command>` to run any command inside the managed environment.
> If you prefer to activate it manually (e.g. for your IDE), run `source .venv/bin/activate`.

### 3. Configure environment variables

Create a `.env` file in the project root with your credentials:

```bash
cp .env.example .env
```

Then fill in the values:

```env
# Neon PostgreSQL connection
PGHOST=<your-neon-host>
PGDATABASE=neondb
PGUSER=<your-neon-user>
PGPASSWORD=<your-neon-password>
PGSSLMODE=require

# Stack Auth credentials
STACK_AUTH_PROJECT_ID=<your-stack-auth-project-id>
STACK_AUTH_SECRET_SERVER_KEY=<your-stack-auth-secret-key>
```

You can find the Neon credentials in the [Neon Console](https://console.neon.tech) under your project's connection settings. Stack Auth credentials are in the [Stack Auth Dashboard](https://app.stack-auth.com) under your project's API keys.

### 4. Run database migrations

Apply all existing migrations to set up the database schema:

```bash
uv run alembic upgrade head
```

### 5. Start the development server

```bash
uv run uvicorn app.main:app --reload
```

The API will be available at:
- **Base URL:** `http://localhost:8000`
- **Interactive docs (Swagger):** `http://localhost:8000/docs`
- **Health check:** `http://localhost:8000/`

## Managing Dependencies

All dependencies are defined in `pyproject.toml`. Use `uv` to manage them:

```bash
# Add a new production dependency
uv add <package-name>

# Add a development-only dependency
uv add --dev <package-name>

# Remove a dependency
uv remove <package-name>

# Update all dependencies
uv lock --upgrade
uv sync
```

> **Important:** Do not edit `uv.lock` manually. It is auto-generated by `uv` and should be committed to the repository to ensure reproducible builds.

## Database Migrations

This project uses **Alembic** for managing database schema changes:

```bash
# Apply all pending migrations
uv run alembic upgrade head

# Generate a new migration after modifying SQLAlchemy models
uv run alembic revision --autogenerate -m "description of changes"

# View current migration status
uv run alembic current

# Rollback the last migration
uv run alembic downgrade -1
```

## API Overview

All endpoints (except health check and auth) are prefixed with `/api/v1` and require the `x-stack-access-token` header.

### Authentication (`/api/v1/auth`)

| Method | Endpoint                  | Description                                  | Auth |
|--------|---------------------------|----------------------------------------------|------|
| POST   | `/auth/register/institucion` | Create institution + admin user atomically | No   |
| POST   | `/auth/register`          | Register user (alumno/docente/admin)         | No   |
| POST   | `/auth/login`             | Login, returns JWT tokens                    | No   |
| GET    | `/auth/me`                | Get current user profile                     | Yes  |
| PATCH  | `/auth/me`                | Update profile (name, email, password)       | Yes  |
| DELETE | `/auth/me`                | Delete account (Stack Auth + local)          | Yes  |

### Data Endpoints (all protected)

| Prefix                       | Resource                    |
|------------------------------|-----------------------------|
| `/instituciones`             | Institutions                |
| `/usuarios`                  | Users                       |
| `/alumnos`                   | Students                    |
| `/admins`                    | Admins                      |
| `/docentes`                  | Teachers                    |
| `/salones`                   | Classrooms                  |
| `/alumnos-en-salon`          | Student-classroom enrollment|
| `/escenarios`                | Learning scenarios          |
| `/actividades-interactivas`  | Interactive activities      |
| `/actividades-alumno`        | Student activity records    |
| `/interacciones-escenario`   | Scenario interactions       |
| `/escenarios-en-actividad`   | Scenario-activity links     |

Each resource exposes `GET /` (list) and `GET /{id}` (detail).

## Authentication Architecture

The system uses a dual-layer authentication model:

1. **Stack Auth** handles user credentials (sign-up, sign-in, password hashing, JWT issuance)
2. **Neon PostgreSQL** stores application user data in the `usuario` table

### Registration Flow

```
Client -> POST /auth/register/institucion
  1. Stack Auth creates user (email + password)
  2. Backend fetches full user object from Stack Auth
  3. Inserts user JSON into neon_auth.users_sync(raw_json)
  4. Creates institucion record
  5. Creates usuario record (authid -> neon_auth.users_sync.id FK)
  6. Creates admin role record
  7. Returns access_token + refresh_token + user info
```

### neon_auth.users_sync Integration

The `neon_auth.users_sync` table bridges Stack Auth and local database records:

- Only `raw_json` (JSONB) is writable; all other columns are generated:
  - `id` = `raw_json->>'id'` (Stack Auth user ID)
  - `email` = `raw_json->>'primary_email'`
  - `name` = `raw_json->>'display_name'`
  - `created_at` = derived from `raw_json->>'signed_up_at_millis'`
- FK constraint: `usuario.authid -> neon_auth.users_sync.id ON DELETE CASCADE`
- The backend manually inserts into this table after Stack Auth user creation (the legacy Neon Auth auto-sync is deprecated)

### JWT Verification

- Algorithm: **ES256**
- JWKS endpoint: `https://api.stack-auth.com/api/v1/projects/{PROJECT_ID}/.well-known/jwks.json`
- Audience: Stack Auth project ID
- Header: `x-stack-access-token`

## Data Model

### User Hierarchy

```
Institucion (1) ─── (N) Usuario ─── (0..1) Alumno
                                ├── (0..1) Docente
                                └── (0..1) Admin
```

### Classroom & Activity Model

```
Docente (1) ─── (N) Salon ─── (N) Escenario ──── (N) InteraccionEscenario ── Alumno
                      │                    \
                      │              EscenarioEnActividad
                      │                    /
                      └── (N) ActividadInteractiva ── (N) ActividadAlumno ── Alumno

Alumno (N) ── AlumnoEnSalon ── (N) Salon
```

### Key Constraints

- `usuario.tipousuario`: `alumno | docente | admin`
- `escenario.niveldificultad`: `principiante | intermedio | avanzado | experto`
- `escenario.tipoescenario`: `simulacion | caso_estudio | problema | proyecto | laboratorio | juego | debate | investigacion`
- `actividadinteractiva.tipoactividad`: `cuestionario | tarea | examen | proyecto | participacion | practica | foro | juego`
- JSONB fields: `escenario.configuracionescenario`, `interaccionescenario.datosinteraccion`
- All primary keys are UUIDs
- All names and attributes are in **Spanish**, matching the database schema exactly

## Development Notes

- The Neon project uses two branches: `main` and `development`
- The backend connects to the `development` branch during development
- Alembic `env.py` has an `include_object` filter that excludes `fk_usuario_auth` from autogenerate (managed externally by Neon Auth)
- Stack Auth DELETE endpoint requires a JSON body (`content="{}"`)
- CORS is currently set to allow all origins (tighten for production)
